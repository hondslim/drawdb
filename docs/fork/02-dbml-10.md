# #2 Upgrade the DBML importer to @dbml/core 10.x

## Spec

- `@dbml/core` is `^10.3.1`.
- DBML written by 10.x tools (`db2dbml`, `@dbml/connector`) parses with no preprocessing:
  - column `check:` settings and table `checks {}` blocks,
  - optional relations (`>?`, `<?`, `-?`, `?<`, `?>`, `?-`, `?-?`), which 10.x reports as `0..1` and `0..*` endpoints,
  - `TablePartial` and `~partial` injection (10.x expands the fields).
- An optional relation imports with the same cardinality as its mandatory form, and is no longer dropped.
- The parser keeps what 10.x adds, so later issues can use it:
  - `field.checks` and `table.checks`: `[{name, expression}]` (#3),
  - `startOptional` and `endOptional` on each relationship (#4).
- DBML exported by drawDB round-trips unchanged.

## Plan

- Bump the dependency.
- `src/utils/dbml/parse.js`: split each endpoint relation into multiplicity (`1` or `*`) and optionality (`0..`), and carry checks.
- `src/components/CodeEditor/setUpDBML.js`: highlight `checks`, `check`, `tablepartial` and `tablegroup`.
- Tests: `src/utils/dbml/__tests__/parse.test.js` (10.x syntax), `roundtrip.test.js` (all templates export, import and export the same DBML).
- Follow-up in dbdraw (not on disk here): delete the check stripping and the `0..1`/`0..*` folding.
